1) When preparing input, I'd like to keep it stored until deleted, so that users can infer using different models without re-uploading input. In the  Prepared Input page we should distinguish the list of prepared inputs (showing input file names and potentially a custom name assigned when uploading new inputs) and the detail page of a specific input. When uploading a new input, after processing it, UI redirects directly on the details page, but one can go back, select another stored input and infer with desired model. Stored inputs can also be deleted.

2) When running inference over a prepared input, one should be able to filter frames using the start:stop:step method, and run inference only on a subset (this info should remain in metadata file on the saved result folder).

3) When parsing the uploaded trajectory, I'd like more informative loading bar, expressing progress in more detailed steps and showing some text describing what is being processed

4) I'd like to add a .sh script which is interactive, where users can list existing processed inputs, run inference over one of them selecting a model, deleting one, adding a new input (file + optional trajectory and name), and have these results reside in the same root folder shared by the docker webserver. The idea is the same used in repo /home/angiod@usi.ch/PHASE where we have /home/angiod@usi.ch/PHASE/venv_setup.sh to install virtual environment and all necessary packages, and /home/angiod@usi.ch/PHASE/scripts/phase_console.sh as the interactive script. The logic is that when running the phase_console script one exports the root directory also used by the webserver and then both the console and webserver work on the same data. Also, all created folders and files should be owned by the user and readable/executable by any user
